# 对白自动分页

`PaginateDialogueText` 已把 CEGUI 整段节点排版转换为分页结果，交给共享 `ConfigureRich`。页界由字体度量计算，逐字和确认由服务拥有；不生成磁盘缓存。

## 原版对照

PC 原对白、原版 `ui.cpk`、800×600、20 像素楷体：`TextGlyph::getHeight()` 为 21.71875。原 `getTextHeight(1)` 每行累计字体行高加 1，分页采用这个度量；绘制额外行距单独应用。修改绘制行距为 0、3、10 时，所测分页边界不变。

| 窗口高度 | 第一页行数 |
| --- | ---: |
| 45 / 45.4374 | 1 |
| 45.4375 / 46 / 68 | 2 |
| 69 / 90 | 3 |
| 91 / 108 | 4 |

相等时允许该行进入本页。页界包括前一行末尾的 LF；文本以 LF 结束时，末尾空文本节点可能单独形成一页，页尾字符位置可与前页相同。该空页仍消耗节点/行转换更新并等待用户确认。

当前只处理同一字体的文本及 LF 节点。高度不足一行时拒绝配置：原控件在高度 22 的翻页测试中持续停在等待翻页状态，本实现未模拟该异常布局。

## 已验证

样本 `A\nB\nC\nD\nE\nF`、窗口高度 46，自动生成三页，结束码点为 4、8、11。安卓模拟器从原 CPK 内存加载字体，经实际排版、服务、确认、窗口绘制走完三页并关闭；36 个行/节点/字符游标、结束及等待翻页状态与 PC 全部一致。前两页各第 8 次更新等待翻页，最后一页第 7 次更新完成，之后等待确认。

文字区域 `(38,483)-(160,529)`：第一页仅 1 个 RGB 像素不同、最大通道差 1；第二页 161 个、第三页 144 个非背景像素，两端 RGB 均逐像素一致。严格比较第二、三页通过，第一页失败。此处刻意使用较矮窗口，保留了 PC 原控件的底部裁剪行为，不代表完整对白页面验收。

![第二页：PC、安卓和差异像素](images/cegui-pagination-comparison.png)

`A\n`、高度 23：两页结束码点均为 2。PC 末页在两次更新后完成；主机及安卓验证空页不会提早关闭、不会残留前页文字，确认后脚本令牌只释放一次。Android ARM64 与 Switch 章节桥接库编译通过，尚未实机验证。

## 复查

- PC：设置 `PAL4_CEGUI_SCENARIO_TEXT_FILE` 为本地 UTF-8 诊断文本、`PAL4_CEGUI_SCENARIO_WRAP=695`、`PAL4_CEGUI_SCENARIO_HEIGHT=46`、`PAL4_CEGUI_SCENARIO_UPDATES=12`、`PAL4_CEGUI_SCENARIO_TRACE=1`。`PAL4_CEGUI_SCENARIO_PAGE_ADVANCES=0/1/2` 分别导出三页；`PAL4_CEGUI_SCENARIO_LINE_SPACE` 可改变绘制行距。
- 安卓：在原字体/自动换行探针基础上设置 `PAL4_CEGUI_PAGES_RGBA_PREFIX`，导出三页并检查高度边界及空白末页。原图和日志位于 `H:/PAL4/objs/pal4-android/emulator/cegui-pages-*`，仅用于开发诊断。
- 使用 `compare_dialogue.py PC.rgba 安卓.rgba --region 38 483 160 529` 进行严格 RGB 比较。主机与安卓 `pal4_portable_dialog_tests` 覆盖重复末页码点、确认和等待令牌生命周期。

正式游戏页面尚未接入 CEGUI 自动分页。不同字号、混合字体、图片等富文本节点、窗口变化后重排及翻页残余时钟仍需验证。
