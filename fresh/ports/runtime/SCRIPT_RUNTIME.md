# 脚本运行时

## 原包执行优先级

发布包不携带原脚本或反编译 `.cs`；用户提供 `script.cpk`。当前优先接通原始 `.csb` 装载执行，暂不实现 `.cs → .csb`。必要的兼容转换只能基于用户文件生成本地缓存。

共享原包读取器已在安卓模拟器读出script/Q01/M01/Music四个原CSB，并与Windows结果核对一致。现已新增[原CSB兼容执行层](CSB_RUNTIME.md)，NewGame与场景入口走原包；尚未覆盖全部指令和剧情。下文2.38编译和调用记录属于恢复源码验证，不能代替原包执行。详见[原始资源](RAW_RESOURCES.md)。

## 引擎与版本证据

恢复源码对照使用官方 AngelScript 2.38，通过 `AS_MAX_PORTABILITY` 的通用接口绑定游戏服务。原CSB使用单独的旧指令兼容执行层；其类型化引用避免原2.2宿主指针截断。旧版2.2 SDK仍用于Windows32位执行对照。不能将旧CSB执行描述为2.38直接装载。

2026-10-26 重新核对 IDA 中的 `I:/Games/PAL4_game/launch.exe`：

- `0x7DE7D1` 执行 `push 4EE8h`，即版本号 `20200`。
- `0x7E4D70` 检查主版本 2、次版本 2、构建号 0，与官方 2.2.0 创建函数对应。
- 官方头文件定义 `ANGELSCRIPT_VERSION=20200`、版本字符串 `2.2.0`。

样本 SHA256：`9b7f7824b47cb6a06893a544323bb4f9692a79321a052aeabb341ce4035f88c3`。
这支持 2.2.0 系列源码对应关系；不能证明官方源码完全未修改或二进制 ABI 相同。原游戏与现代工具构建的回调记录尺寸已有差异。

## 源码与准备流程

章节源码以用户验证的目录为准：
`I:/Games/original/gamepatch/gamedata/EditData/script`。
该版本保留完整对白和语音编号，不能用未经验证的新反编译稿覆盖。

`prepare_chapter_scripts.py` 读取 script/Q01/M01/Music 四个完整模块，严格解码 GBK，再输出 UTF-8。清单保留原文件、转换文件、工具及校验器哈希；全部编译通过后才写入资源目录。原始资源不提交到 Git。

旧版使用 `strtod`，新版自有小数解析器对 0.3 等值存在一位精度差异。`script_source.py` 跳过字符串、注释、标识符和十六进制整数，将十进制小数转换为 `pal4DoubleFromBits(uint64)`，保留旧版解析后的 IEEE 数值。此转换不证明所有浮点运算均与旧版完全等价。

## 上下文、等待与生命周期

`ScriptSession` 持有独立上下文，借用全局变量和服务。`Fork` 共享引擎、编译模块和模块变量，不复制模块状态；原创建者销毁后，引擎仍由存活上下文持有。

`ScriptStack` 在同一游戏线程中工作：

- 支持准备、挂起、恢复、结束、失败和取消。
- 新场景初始化使用新上下文，完成后弹栈，调用者保留原指令位置。
- 活跃入口按 ASCII 大小写不敏感去重；缺失初始化入口不改变栈。
- 活跃上下文存在时可新增模块，但不能替换已有模块；执行期间拒绝重入修改。
- 模块全局初始化阶段禁止调用游戏服务，避免在未绑定的上下文中执行。
- `giWait` 使用与现有 `ScriptWaitHandler::Update` 相同的剩余时间规则。零或负等待也先挂起，到下一次更新释放。
- 外部服务使用“上下文 ID＋请求序号”完成等待；过期或重复通知不能释放新的等待。
- 时间由调用者传入；暂停时不推进。下层上下文的计时不随栈顶自动推进，具体场景等待清理仍由加载服务负责。

当前栈管理只提供调度机制。真实场景加载仍需在资源准备完成后结束加载等待，压入目标初始化，再恢复原调用者，不能把记录服务当作实际加载。
