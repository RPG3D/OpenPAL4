# 怪物构造成员组合

MonsterObjectMembers通过共用ConstructMembers入口执行原4312A0：基础对象→事件处理器→脚本任务容器→工厂表→回调与自身引用→工厂0～3注册→状态初值。Win32原Construct现只适配该入口，保留原顺序和失败逆序回收；不复制另一套标量初始化。

## 成员与所有权

调用方提供空的0x73c状态图像、稳定逻辑身份、ObjectMemory、实际动作工厂、行为定义、持久记忆节点及随机服务。各依赖须比组合对象活得久。基础成员使用BorrowedActorBaseMembers；处理器和队列在原构造阶段各建立一次，工厂注册延后到原指定位置。

原处理器构造只建立记忆视图；PrepareBehavior才准备行为事件与候选数组，不自动启动任务。构造不调用动作工厂、不选择模型动作、不推进剧情。动作工厂不得用空成功替代未实现的辅助对象；四项注册也不表示实际移动工厂已支持class2。

工厂表由队列中的std::map拥有。便携图像的原STL头指针6a0为0，6a8显示实际注册数；不伪造旧树节点。原函数/虚表地址仅为行为身份，不能作为宿主函数指针调用。原Win32树实现继续由旧适配器使用。

## 关闭与失败

先关闭基础运动并确认动画恢复，再显式调用成员Close。组合取消任务，清理工厂表和任务容器、原处理器，最后执行原基础对象析构。重复关闭安全。不要对便携对象调用依赖旧STL图像的MonsterBehaviorManager::Destroy。

尚未交还的动画、非空接敌位置/历史数组或回调数据会在释放前拒绝。调用方必须观察Close错误，不应依赖析构兜底来证明清理成功。构造异常沿用原逆序回收，并恢复输入图像与记忆节点原名称。行为准备失败会关闭处理器，随后仍可Close其余成员。

原包members-lifetime-source探针已组合原成员构造、实际缓存模型、资源逐帧服务、播放器、网格、移动辅助对象与追逐循环。M01八只、M02十二只均结束到零对象分配；追逐报告相对旧基础对象路径仅初始主虚表改为怪物类型，其他字段一致。此前construction-source的合同辅助对象边界保持，不扩大其证据范围。
