## 调度与所有权

IDA `5D30E0` 的原回调未读取第四个bool；它切入加载状态，并在ArenaManager非ready时忽略重复请求。共享 `ArenaServices` 保留三段名称、请求标识与ready门控；第四个bool不控制装载。

跨平台实现另设内部装载屏障：服务记录请求后挂起当前上下文，GL线程在Tick返回后处理CPU/GPU资源，再压入场景初始化、释放原调用者的等待。它用于避免重入修改脚本栈，不表示原接口支持按bool阻塞。场景初始化结束后弹栈，调用者从原位置继续；失败、旧通知或取消不能释放另一次请求。

`ArenaResources`持有本场景CPU数据；N01为4份、Q01为37份NPC/GOB模型资源。GPU上传世界、选中玩家、NPC和GOB类型0/6/7；室外实际15个GOB/1722三角形，76另提交1个NPC/794三角形。NPC行为、机关、特效和事件仍未绑定，完整entity/gameplay标志继续为false。脚本镜头已有独立公共模块。切后台只重建GPU对象，保留场景、玩家、NPC/GOB动画及显隐和脚本栈。

## 原始数据

共用原 `BinaryXmlConfig` 读取器，不复制原x86对象或内部文本地址。文本保留原字节；资源名称为ASCII，原配置中的GBK文本尚未用于UI显示。

| 输入 | 保留内容 |
| --- | --- |
| GameObjs.gob | 类型表、名称/目录/模型/变体、变换、入口、四个标记、完整Binary XML |
| npcInfo.npc | 三段文本、变换、三个标记、行为和缓存配置、默认动作 |

各读取器限制文件和数量，拒绝截断、尾随、非法变换、重复名称与损坏XML。N01包含1个NPC、4个GOB、2个事件体、5个CAM文件；怪物和路径为空。原怪物和路径文件现在均可独立读取；公共路径查询拥有者见[场景路径](SCENE_PATHWAYS.md)。联合装载仍对非空怪物/路径保持玩法绑定门禁，不返回空集合代替，也不将解析成功算作场景可玩。

类型0、3、5、6、7均可装载模型与原配置，并在ArenaActor保留GOB类型；这不等于它们的机关/拾取/声音/动画更新已经接通。类型8仍保留原记录，效果播放待接入。模型转换按原directory、model定位，并按原59A220/667450的单纹理变体分支选用存在的variant.png；变体缺失时保留原贴图，多纹理替换暂明确失败。
