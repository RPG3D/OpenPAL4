# 共享移动控制

PC 适配器和安卓共同调用 `fresh/include/pal4/actor_vector_movement.h`。原 `DispatchVectorMovement` 委托给适配器；地址读写保留在 x86 边界，跨平台层使用类型明确的状态。

保留的流程顺序：相机 → 位置 → double 时间/速度乘积缩为 float → 上一帧模型前向行 → 边界 → C02/C03 → 预处理 → 地面更新 → 许可 → 写入位置、朝向和地面。拒绝时跳过最终写入；原接口仍返回1，类型化接口返回是否允许。

## 当前静态服务

安卓将键盘和触控转为相机相对水平输入。静止使用 C01，移动使用 C02/C03，组合角色必须包含三个原始动作。

碰撞适配器使用前缘半径线段和限定高度的地面查询；障碍前将位移缩为0，保留转向和反向脱离能力。缺失地面时拒绝提交。尚未实现原版滑墙、球体测试、地面属性/事件、动态 GOB 和二级碰撞。

速度120、身高72、上台阶16、下台阶32是调试参数，不是已读取的原控制器属性。输入归一化尚未对照原查表数学；安卓预览将帧间隔限制为50ms，不代表原游戏时钟。

同场景 EGL 重建保留位置、朝向和计数；暂停或切资源时清空输入。相机跟随角色，移动选择动画；AMF、混合、剧情动作覆盖仍待接入。

## 验证

Win32/x64 测试覆盖调用顺序、属性读取、原始3D位移、动画模式、碰撞修改/拒绝和提交后朝向。函数 0x427E70 的归属仍待审查，不据此宣称原进程轨迹完全一致。

跨平台测试覆盖旧朝向移动、墙面阻挡/脱离、缺地面和非法时间。原 N01 碰撞数据上，300步前进移动16单位后被阻挡，并保留有效来源地面。

`verify-movement.ps1` 注入真实安卓键盘/触控事件，检查移动、撞墙后位置稳定、反向退出、释放输入及 Home/恢复。触控坐标来自实际界面层级。测试依赖 API35 的持续按键命令，尚未在 API33 手机核对。

这些检查只验证预览移动；完整游戏碰撞、剧情出生点和章节流程仍未验收。

## 真实章节接线边界

当前Android `nativeMove`写入输入值，但逐帧消费仍限于独立level预览；ChapterHost没有把这些输入接到原自由控制流程。不能以控制器enabled为true宣称已能自由移动。

已重新核对原0x428630：相机前向来自LTM+0x20，侧向来自LTM+0；后退覆盖前进，侧向按原顺序叠加，最后由既有NormalizeAndClamp和向量移动处理器执行。该回调属于游戏输入路由，RW取矩阵使用公共边界。便携控制器现已复用ActorControlInputComponent与游戏向量数学，独立原生测试通过；下一步仍需核对上层输入清理/模式选择，并接入ChapterHost、原碰撞及地图/相机更新。预览中的速度120和身高72仍是调试值，不能直接当原角色属性接入实际剧情。

自由控制速度已从原428190确认并绑定为控制器模式计算，见[控制器](CONTROLLER.md)。这只解决速度来源，尚未将预览碰撞作为真实章节移动使用。

原三组碰撞现已有独立便携适配器，并通过主机、安卓原生及原场景缓存装载检查，见[场景碰撞](SCENE_COLLISION.md)。它尚未替换预览碰撞，也未绑定ChapterHost；不能据此宣称真实剧情已能移动。

## 原资源单帧提交

独立PlayerFreeMovement已连接原输入、双球碰撞、地面高度回写、动作/位置/朝向和属性通知，详见[玩家自由移动](PLAYER_FREE_MOVEMENT.md)。N01/Q01在主机和安卓的离线原资源探针通过；相机/HUD服务与配置对象仍未绑定，ChapterHost尚未消费这条链路。独立预览继续使用上述调试移动策略，不能混为真实剧情实现。
