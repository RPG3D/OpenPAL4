# 影片标记与持久化

`SettingsServices` 已接入 `giOpenMovieFlag`（110）。PC 回调与跨平台服务共用 `movie_flag_value.h` 的位操作：只接受0～31，保留其他位；无效索引不保存。同一位重复解锁仍调用保存，保留原接口行为。

原游戏将标记放在全局设置的 `+0x18`，随后通过 `DialogManagerSettings::Save` 写入 `pal4.set`。该对象包含其他设置与32位布局，安卓不会直接序列化它，也不会覆盖或导入原PC文件。

## 跨平台文件

安卓将 `pal4-port.set` 保存到应用私有目录。当前格式为 P4ST v4，固定64字节，全部小端：

| 字节偏移 | 内容 |
| --- | --- |
| 0 | 4字节 `P4ST` |
| 4 | uint32 版本4 |
| 8 | uint32 影片解锁位集 |
| 12 | uint32 教程开关（0或1，默认1） |
| 16～27 | 三个 uint32 答题结果，保留原始位模式 |
| 28～59 | 八个 uint32 帮助已读位，共256位 |
| 60 | 前60字节的CRC32 |

读取兼容v1/16字节（教程默认开启）、v2/20字节和v3/32字节。缺少的答题结果及帮助已读位初始化0，下次保存写v4；旧运行时不能读取v4。教程已读位属于当前游戏的128位状态，与帮助的256位状态独立。`SaveTutorial` 对0～127编号执行设置保存后才显示窗口；这不代表已实现原版全部设置或存档迁移。

`Settings::HelpSeen` 查询0～255编号，越界返回false。`SettingsServices::MarkHelpSeen` 仅首次已读时保存，重复或越界不写盘；保存失败保留旧内存与旧提交，避免界面误显示为已读。影片、教程选项和答题结果不受帮助保存影响。行为依据原版 `HelpWindow_OnItemClick`（IDA `0x4A7890`，全局对象 `+0x54`）。帮助窗口现已接入并完成部分实际游戏同输入验收，范围与未验收项见[帮助运行时接线](../android/帮助运行时接线与同输入验收_20261103.md)。

`FileSettingsStore` 在主文件和提交备份均不存在时使用默认值0；主文件缺失但有`.bak`时读取旧提交。格式、版本、长度或校验错误会明确失败，不自动覆盖损坏数据。

保存先写完整`.tmp`、刷新并关闭，再将旧正式文件移至`.bak`、把临时文件移成正式文件。这样不依赖FAT/libnx不支持的覆盖rename。提交失败尝试恢复旧文件，未能恢复时保留备份供下次Load读取；新文件已提交后的备份清理失败不误报为未提交。该策略不宣称断电文件系统级原子性。内存标记只在保存成功后提交；写入失败不把未保存的位显示为已解锁。只有一个游戏线程负责写入，资源切换和新游戏不会清除影片解锁状态。
