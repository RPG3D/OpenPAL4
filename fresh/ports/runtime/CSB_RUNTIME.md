# 原始CSB执行

## 路径与实现

游戏脚本路径为 `用户script.cpk → PackageReader → ReadCsb → CsbExecution → ScriptStack → 游戏服务`。NewGame及场景初始化不读取恢复 `.cs`，也不在准备阶段重新编译用户脚本。

`ReadCsb` 沿用已验证研究解析器的字段顺序：类型、函数、对象局部变量、栈空间、字符串及导入记录。读取长度固定为原始格式的1/2/4/8字节；保留原始GBK字符串。指令记录同时保存文件位置和展开后的VM位置，跳转只允许落在指令边界。

`CsbExecution` 是旧指令的兼容执行实现，部分语义改写自官方AngelScript2.2的 `as_context.cpp`，不是把原CSB交给2.38装载。数值仍是32位槽；栈和全局引用使用检查过的索引，字符串使用明确的对象所有权，不将64位宿主指针截断为DWORD。

官方2.38仍用于恢复源码的开发对照。两个后端共用 `ScriptSession/ScriptStack` 的游戏服务、异步请求和取消接口；原CSB执行失败时不回退到恢复源码。

## 当前优先级

先补齐原CPK中的CSB装载、指令语义、原生服务与异步完成链，暂不实现CS到CSB编译器。每段流程都以真实原包执行为验收依据；源码对照和记录服务不替代实际玩法。

第120号服务已接入原8450处理器、P4AR v3映射、同姿势矩阵与GPU实际提交；已完成后续66。257 `giPlayerWalkTo`、258 `giPlayerRunTo`与267 `giPlayerEndMove`已接原路径、逐帧运动及完成处理器。154 `giGetVisibleObject`使用当前SceneObjects的+0x184对应字段；原 M01/1 缺失对象查询返回false后到210 `giGOBReset`，该服务尚未接线。272 `giNpcDoAction`已复用原处理器与场景播放器；当前真实边界为97对`Jeffect001`的类型8特效显隐链，不是VM装载或CS编译问题，见[距离插件](ATOMIC_DISTANCE.md)与[玩家行走](PLAYER_WALK.md)。

## 原步进调度

实际游戏使用 `original_steps`，在原SUSPEND和系统调用返回处按原ExecuteStep(0)规则让出。55/56复用原立即模式处理器，每个脚本上下文保存current/previous；只有一个保存位。影片、对白、动作和镜头的真实等待继续阻塞立即模式。源码对照后端不接受此模式。

三份原CSB与32位AS2.2逐帧记录已完全一致：NewGame 24帧/8调用、Q01_Q01_init 18帧/4调用、Q01_N01_init 450帧/165调用。记录服务不证明实际玩法；输入、执行器及trace哈希见本地 `emulator/csb-original-steps-comparison.json`。详细规则与边界见[原CSB步进与立即模式](SCRIPT_IMMEDIATE.md)。

- 已支持NewGame所需的数值、局部引用、字符串工厂/释放、全局变量及系统调用。
- 内部CALL/RET保留调用者的函数、PC、帧和栈位置；覆盖参数弹出、整数返回值和在被调用函数内挂起后继续。
- 外部服务挂起后从下一条指令继续；语句预算在此后端按指令计数，预算挂起保留临时值。
- 模块活跃时禁止替换；取消及失败使用现有脚本栈令牌规则。
- 不支持的指令、对象类型、模块全局初始化或导入明确失败，不按空操作继续。

**尚未覆盖全部123种旧指令。** 公共运行时已提供严格 CP936 解码器，Android 的原 script/Q01 装载显式使用它；没有配置解码器的调用方仍拒绝非 ASCII 文本。解码不等于对白绘制或等待已经实现，石沉溪洞剧情与战斗尚未验证。

CP936 使用通用 Unicode 映射，来源、授权及生成命令见[码表说明](../../third_party/unicode-cp936/PROVENANCE.md)。21791 个双字节映射与 129 个单字节参考对照通过；非法、截断和未映射字节明确报错，不用替代字符掩盖错误。公共模块不依赖 Android 字符集接口，供后续 Switch 复用。
