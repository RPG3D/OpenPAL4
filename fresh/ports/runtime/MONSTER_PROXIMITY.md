# 怪物接敌距离与返程探测

2026-10-29 新增 `MonsterPlayerView`：从当前控制器和玩家队列读取角色活动位、位置及既有模型绑定球，按角色变换计算世界球心，并解析玩家逻辑 token 对应的追逐目标。控制器关闭、未选择角色和玩家离场均不会被视为活动目标；无模型包围球或无效 token 明确失败。主机及安卓合同覆盖角色切换、旋转与非法身份；两端读取原数据库和四名角色 CPK，快照报告逐字节一致。这里角色位置和旋转由探针设定，球心沿用已验证的资源初始化计算；尚未对照原 PC 的实时玩家内存，也未连接怪物场景、交互或战斗。玩家 token 使用现有章节布局，场景所有者必须保证怪物 token 不与玩家冲突。

MonsterProximity复用原433C50、433DA0、433E10，提供后续追逐状态机需要的三项服务；未连接完整追逐/战斗，也不放开非空怪物场景门禁。

## 数据与顺序

借用实际MonsterBehaviorManagerState、已绑定变换的SceneMonsterInstances、当前场景CollisionMesh及受控角色快照服务。token仅作逻辑身份，不编码宿主地址；状态、实例和墙体必须比组件活得久，场景重载时重建。管理器+654须匹配当前源记录标识。

检测半径直接读取原mstInfo记录+34，即SceneMonster.fields[1]的float位值；不从行为XML猜测或另造默认值。使用原GameVectorMath近似长度表。先清追逐目标，再检查受控角色活动位、水平半径、高度差严格小于两倍半高，最后以怪物/玩家世界球心检查移动墙体遮挡。没有墙体时保留原433650的无阻挡分支；不以渲染世界替代移动墙体。

命中时保存怪物当前逻辑位置为追逐起点。返程阈值保留1000和0.05f；到达时经实例绑定入口提交保存位置，同步管理器变换与球心，不直接改原出生记录。有限输入、绑定状态与重入检查属于宿主边界保护，不宣称复现损坏/NaN原数据。

## 验证与限制

主机/安卓生成模型合同覆盖活动、远近、高度等值拒绝、真实三角形墙体阻挡、返程回写、源标识变化、非法快照、重入与异常后重试；原路径/随机/基础运动合同保持通过。

两端直接读各自原scenedata.cpk与既有模型/碰撞缓存，M01/1共8只、M02/1共12只的完整探针报告逐字节一致。原半径位值、同点检测、远距离/非活动拒绝、追逐起点保存及源位置保留通过。探针管理器初始图像与玩家快照仍受控，同点检测不验证原场景墙体遮挡；墙体阻挡另由生成三角形合同覆盖。没有执行CSB、GPU渲染、实际追逐或战斗。
