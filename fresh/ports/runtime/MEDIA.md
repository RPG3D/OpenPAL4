# 视频与音乐传输

## 资源准备

Android 媒体控制器已接入原 `videoa.cpk` 的 BIK 解码与播放，不需要转换 MP4。旧 `prepare_android_media.py` 和下方历史验证仅供对照，旧转换文件不属于发布包。

背景音乐不经过转换。原生层通过 `PackageReader` 从用户的 `Music/p23.smp` 读取并解密 `p23.mp3`，向 Android 的 `MediaDataSource` 传递内存字节，不生成临时媒体文件。原音视频不放入 APK。

独立安卓模拟器音频探针验证了内存 MP3 的准备、启动和约 6 秒进度，以及内存 WAV 的准备、启动和自然结束；探针样本单独准备，不证明游戏路径的完整媒体交互。ARM64 原生库已交叉编译，真机播放尚待验证。

原 BIK 解码：`build-bink-ffmpeg.sh` 使用 FFmpeg 7.1.1 和 Android NDK r27d 构建 LGPL 最小库，启用 Bink 容器、视频和音频解码。独立 `android_bink_probe` 经公共 `PackageMemberStream` 和 FFmpeg 自定义 IO 从模拟器的 `videoa.cpk` 直接读取。原样成员按需读取；压缩或加密成员在限额内解码到内存，其随机读取及边界已用构造包测试，尚未以对应 BIK 实测。ARM64 共享库交叉编译通过，未在 ARM64 真机运行。正式分发时需提供 FFmpeg LGPL 许可证及相应合规材料。

`BinkDecoder` 输出带时间戳的 RGBA 视频帧和双声道 16 位 PCM。模拟器完整解码 `1A.bik` 至 EOF：855 帧画面、655 帧音频，结束时间约 28.47 秒；`PAL4A.bik` 为 6001 帧画面、4595 帧音频，结束时间约 200 秒。控制器独立探针已自然播放第一段并回传正确请求 ID；截图有画面，音频输出完成 628800 帧，独立播放器暂停两秒恢复后仍完成 855 帧。第二段控制器完整播放、音画同步精度、系统表面重建及实际新游戏仍需验证；当前表面销毁会向脚本报告错误。

安卓调试包可通过 `android-dev.ps1 build -Abi x86_64 -NoBundledAssets -FfmpegRoot <FFmpeg输出目录>` 链接解码器。模拟器 JNI 探针从两段原包视频各读取 20 帧画面和 32 帧音频，缺失成员返回明确错误；ARM64 共享库已交叉链接，尚未真机运行。该探针不播放或推进游戏。

旧转换媒体的开发对照命令如下；其中构建会打包开发资产，不用于发布：

```powershell
pwsh -File fresh/ports/android/android-dev.ps1 prepare-media
pwsh -File fresh/ports/android/android-dev.ps1 build -BundledDevelopmentAssets
pwsh -File fresh/ports/android/android-dev.ps1 deploy -Device emulator-5556
pwsh -File fresh/ports/android/verify-media.ps1 -Device emulator-5556
```

需要已安装的 FFmpeg/ffprobe；转换器也可显式指定路径。

## 跨平台边界

共享 `MediaServices` 处理127（脚本音乐）、237（暂停音乐）、238（恢复音乐）和297（视频），不依赖JNI、MediaPlayer或libnx。127复用现有 `BackgroundMusicPlayer::PlayScriptTrack/LoadTrack` 生成播放计划；平台实际准备并启动后才确认请求、提交音乐状态和解除等待，不等待整首曲目结束。

IDA本轮重新核对0x514200和0x514400：第三参数是首次淡入，大于0.1秒才生效；第四参数按原位模式保存为恢复时淡出参数。切换前固定淡出1秒。P23调用的模式2循环播放、首次淡入0、恢复淡出2.5秒。模式1的单次播放/恢复链、Music模块场景默认曲目及128停止服务尚未接入，调用时明确失败。

每个请求包含游戏代次与操作ID，内部关联原脚本请求标识。未分发、重复、过期代次或旧ID的完成消息被拒绝。播放器错误使等待上下文进入失败状态，不把错误当作播放成功。取消先停止脚本所有权，再取消平台播放，旧回调不能推进新游戏。

Switch已复用同一请求/完成接口，平台播放边界见文末及Switch性能文档。

## 安卓后端

`MediaController` 在主线程拥有 MediaPlayer 与 TextureView，GL线程拥有脚本栈；完成事件通过 `queueEvent` 返回。画面保留4:3比例并居中留黑边，不拉伸到16:9。

独立 `MusicTransport` 拥有音乐播放器、切曲淡出及播放采样。音乐事件使用自己的成员名和请求身份，不混用视频的movie字段。准备确认与持续播放分离；准备失败使127等待失败，启动后继续播放失败会显示错误。代次取消和销毁会释放音乐及淡出中的播放器。

后台暂停实际播放器；前台恢复继续当前位置。纹理表面丢失时解除输出并暂停，重建后重新绑定；不以重新调用脚本入口恢复视频。销毁时释放播放器、输出表面和定时采样任务。

NewGame前半段237/238确认的仍是空闲音乐传输。进入N01后，P23已实际加载，并另行验证Activity后台暂停和前台继续；这不等于已验证237/238对有声曲目的操作。视频AAC和音乐MP3均有实际解码记录，设备扬声器听音仍需真机确认。

## 已验证范围

模拟器已自然播放两段视频，约28.56秒和200.08秒。`media-events.jsonl` 记录：

- 准备信息：800×600、一条视频轨与一条音轨。
- 真实首帧、播放位置、纹理更新数量及定时画面采样值。
- 后台暂停、前台继续和自然结束。
- MediaPlayer 指标中的实际 H.264 / AAC 解码器、帧数和掉帧数量。

完整报告为 `emulator/media-verification.json`。验证器核对已安装APK、两段自然时长、变化的非黑画面、音轨、暂停恢复、同一进程，以及NewGame八次调用加BGM127、相机103、同队长70、跟随标志105、玩家锁定74和出生点250；不跳转进度或合成结束通知。已在视频播放时检查实际系统截图。

报告的 `music` 保存原包及解密音频哈希、原MP3探测信息、实际播放器信息和播放样本。P23解密结果2996139字节，实际解码器为 `c2.android.mp3.decoder`；平台时长124813毫秒。历史测量中后台位置9371毫秒保持，恢复后推进到10287毫秒；本轮实际位置见报告，同一请求只准备一次。本轮验证首曲及生命周期，未验收跨曲目淡出或完整循环一周。

`verify-screen-effects.ps1` 单独验证首个淡出和取消返回预览，会主动取消第一段视频，不属于完整播放验收。完整报告与短流程报告分别保存。

## Switch视频跳过与混音（0.2.3）

X只跳过正在播放的视频，截图使用系统截图键。公共SkipMovie校验generation/id与已派发的视频类型，完成该脚本令牌；MoviesSkipped单独计数，不增加MoviesCompleted。主机覆盖旧代、错误ID、重复、未派发、非视频拒绝，以及跳过后继续第二段、恢复音乐和后续脚本。失败、自然EOF和跳过各自保留日志。

Switch视频仍用libmpv解码原Bink，结束/跳过后销毁视频输出。场景音乐和WAV改用一个SDL_mixer设备（48kHz、S16、立体声，32个音效通道），解码与重采样交给公开库；主线程查询播放状态并向公共SoundServices投递事件，不在音频线程操作游戏状态。通道由样本拥有者保留到释放，防止旧句柄停止新样本。背景音乐和音效不再分别创建原生播放器。

0.2.2实机两段视频自然EOF、有有效第二段截帧；首次WJ001与P23并发后系统audio进程User Break。原音乐44100Hz/stereo、音效22050Hz/mono，崩溃报告Result0xC0899。0.2.4实机已通过20句对白及多次混音；随后因缺WJ025.wav停止，已定位为资源缺失。当前若已打开场景音频后再请求电影，或电影期间请求并发音效，会明确失败，不重复创建原生输出；完整媒体交接、曲目交叉淡出和后续章节仍待实现。


## Switch 0.2.6媒体输入

原样视频使用libmpv公开stream_cb和PackageReader::ReadRaw直接按需读CPK，压缩视频解包到RAM，音乐通过SDL_mixer内存流播放。播放不再创建临时媒体文件；具体生命周期、限额及性能边界见[Switch性能](../switch_game/PERFORMANCE.md)。原CopyTo仍是通用提取工具，不再用于Switch视频播放。
