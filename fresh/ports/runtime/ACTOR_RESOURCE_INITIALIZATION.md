# 怪物主资源初始化

InitializeActorResource 为已载入的单主体建立原 GameResourceManager 前92个 word，替换独立探针中的手填初值。复用原构造665B20、包围盒667A40、装载收尾和位置/旋转更新；不代替 BaseObject 或 MonsterBehaviorManager 完整构造。

## 输入与发布

原 PackageReader 检查实际 DFF、UVA 和独立阴影。主体必须存在；动态伴随资源暂不支持，明确拒绝。模型缓存必须包含 P4AR v4 原始顶点，旧缓存不伪造包围盒。只支持单主 clump 和单位缩放，身份由调用方提供。

先在临时资源图像中完成构造、原始顶点包围盒/球、收尾、位置再旋转，成功才提交前92个 word。保留原顺序：旋转不顺便更新球心；后续位置更新按原核心处理。状态其余部分不变；已构造或已绑定实例拒绝重复初始化。位姿小接口 IGameResourcePoseRuntime 与完整资源服务共用原核心。

## 已构造对象的绑定

BindConstructedActorResource 接受已经构造但尚无主体的资源视图，供后续完整怪物对象组合使用。它复制现有前92个 word，在临时副本完成相同计算后提交；不再调用资源构造，不覆盖派生虚表、路径/配置/字典身份或后续成员。要求主/第二 clump 与装载完成标志为空、六个缩放值均为1、实例尚未绑定变换。失败保持整个管理器图像不变，重复绑定明确拒绝。

该接口只绑定借用的静态主体，不取得模型所有权，也不代替原 LoadClump 的清理、路径分配、纹理/动态资源装载。调用者仍负责先完成真实对象构造，并在销毁前解除借用；不能据此移除章节的非空怪物检查。

实际移动拥有者现可先构造原怪物成员，再调用该入口绑定模型，保留怪物虚表和后续成员。原模型组合探针见[怪物构造成员](MONSTER_OBJECT_MEMBERS.md)，不再以全零主资源初始化替代对象构造。

新增验证：主机5项合同、安卓模拟器行为合同通过；两端原包 M01/1、M02/1 共20个实例比较两条入口，除预置的虚表与配置等保留字段外，完整图像相同。覆盖重复绑定、空身份、已有主体/第二主体/完成标志、非单位缩放和缺少原始顶点的失败不发布。后续追逐报告两端一致；这里的已构造输入仍是受控主资源图像，未证明完整怪物构造或章节接入。证据：H:/PAL4/objs/pal4-android/constructed-resource-binding-probe。

## 验证边界

主机5项回归、安卓模拟器3项合同通过，含直接/相对根边界。原 M01/1 八只、M02/1 十二只实例接初始化后继续实际资源更新和追逐循环，完整报告主机/安卓逐字节一致，分别730/1066帧追逐、754/1102次资源调用；包含16/24次原门控跳过。源探针另覆盖重复初始化、非法身份、缺少原始顶点时不发布，以及保留后续管理器字段。Android 双 ABI 公共库及 Switch 完整 NRO 构建通过。

独立 Win32 SDK 对照20个实际实例，除物理 clump 身份外，构造默认值、变换及包围盒字段逐位一致。差异仅在52～59的局部/世界包围球，最大绝对误差0.00238037109375。原合并回调调用 SDK RwV3dLength，便携边界当前使用标准 sqrt，未证明数值等价；保留差异，不改写已确认归属 SDK 的内部算法。

源探针的 mode=0、extra=1 以及玩家/随机/内存/世界碰撞、交互/组动作/战斗服务仍受控。名称树、完整管理器构造、标签与配置/纹理载入、动态资源、ChapterHost 和战斗集成未完成。独立测试不等于已跑通 CSB 剧情；没有启动游戏或更新设备安装包。

证据：H:/PAL4/objs/pal4-android/actor-resource-initialization-probe；SDK差异见 sdk-comparison.json。
