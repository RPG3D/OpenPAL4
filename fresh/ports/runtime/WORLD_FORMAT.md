# 世界组合与碰撞资源

`pal4_portable_world` 持有类型明确的地面/墙面和实例数据，不依赖平台或 GPU。线面求交直接复用 `fresh/src/collision_triangle_containment.cpp`；相关函数归属审查仍为 `OWNERSHIP_REVIEW_REQUIRED`，不据此新增逆向完成认定。

## 转换与查询

`prepare_android_level.py` 读取原 `scenedata/世界/场景/*_floor.dff` 与 `*_wall.dff`，应用原 atomic 骨架变换，保留 atomic、材质和三角形来源索引。拒绝蒙皮碰撞体、非法引用；源文件哈希随组合定义记录。

组合预览的 `FindFloor` 在原求交结果上限制上下高度范围并选择最近地面。`SegmentBlocked` 限制到有限线段，避免原无限直线助手接受后向交点。[地面颜色属性](FLOOR_ATTRIBUTES.md)已接入玩家位置服务；运动中的属性更新、实际脚步音效、战斗区域、动态 GOB、滑墙、台阶策略、事件与二级碰撞子对象仍待接入。

游戏放置使用 `FindFloorFromAbove`：从 `y+above` 向 `y-below` 查询，取从顶部首先遇到的面。`SceneMovement` 复用原 `PalMovementAdapter::SelectAndUpdate/CheckActive`，比较主/次子对象的高度分数并保留切换规则；不在这一步擅自吸附玩家高度。安卓当前只绑定静态地面，EVF/GOB二级几何及完整运动碰撞仍待接入。放置流程见[玩家位置](PLAYER_PLACEMENT.md)。

## 格式

全部小端，无本机指针或对齐填充。

| 格式 | 内容 |
| --- | --- |
| P4CL v1 | `P4CL`；uint32 版本1、地面数量、墙面数量；先地面后墙面记录 |
| 三角形记录 | 9 个 float32 坐标；uint32 来源 atomic、材质、三角形索引 |
| P4CL v2 | 头部版本2；每个三角形的v1记录后追加uint32颜色存在标志、3个uint32原始RGBA；无颜色时标志及三个值均为0 |
| P4LV v1 | `P4LV`；uint32 版本1；世界和角色两个 ASCII 名称（uint32 长度＋字节）；3 个 float32 坐标及 float32 角度 |

转换器生成P4CL v2；读取器兼容v1，但不会为旧缓存伪造地面颜色。v2能区分原模型无颜色与旧缓存缺少字段。P4CL要求非空地面、总量不超过一百万，拒绝非法计数、非有限坐标、未知颜色标志、无颜色时的非零数据、截断和尾随字节。P4LV角色名需以 `actor_` 开头。世界P4SC、角色P4AR和碰撞P4CL独立加载。

`InstanceMatrix` 提供列主序 Y 轴旋转和平移，不修改角色原顶点。当前组合预览只持有一个角色，完整场景仍需多实体所有权。

## 绘制与证据

每帧只执行一次 `BeginFrame`；`DrawScene` 共享深度缓冲，使用各自模型矩阵。角色和世界分别持有 GPU 资源；动画只更新角色顶点；EGL 丢失后重新上传。

GPU 检查通过模型平移反转两个独立资源的深度顺序，验证前景红三角仍可遮挡后绘制的绿色背景，可发现重复清屏、深度丢失和遗漏模型矩阵。

N01 预览位置显式为 (-158,7.3,40)、朝向180°，不是安卓新游戏脚本生成的位置。原地面查询得到 y=7.27765、来源三角形39；碰撞数据共105地面、102墙面。

CPU 测试覆盖叠层地面、范围/方向限制、源索引、模型变换及非法文件。`verify-level.ps1` 检查组合、动画、上下文恢复和资源往返；这不证明完整碰撞或第一章可玩。
